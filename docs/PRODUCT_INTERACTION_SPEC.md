# 象棋X（XiangqiX）产品整体交互逻辑与后端对接文档

> **文档状态**：当前生效版本（对应前端工作台最新实现）  
> **维护约定**：本文档为产品交互逻辑与前后端接口对接的单一事实来源（Single Source of Truth）。**后续每次产品交互、状态流转或数据结构调整时，须同步更新本文档及文末变更记录。**

## 一、 整体布局与信息架构

应用采用桌面级单屏无滚动条布局（`100vh × 100vw`，`overflow: hidden`），由上至下分为三层结构：

1. **顶部导航栏（Titlebar）**
   - **左区**：品牌印记（「象棋X」，点击回到「复盘分析」）。
   - **中区**：四大核心工作空间导航——`复盘分析 (study)`、`残局题库 (challenge)`、`人机对弈 (play)`、`摆子编辑 (setup)`。
   - **右区**：全局工具与偏好入口——`棋谱库 (含实时总谱数统计)`、`导入 / 棋谱`、`连线`、`命令面板 (⌘K)`、`音效开关`、`深浅主题切换`、`设置中心`。
2. **主工作台（Main Stage + Right Sidebar）**
   - **左侧主画布区**：上方棋手席位条（`PlayerSeatBar`，摆子模式隐藏）+ 胜率评估柱（`EvalBar`，仅复盘分析模式显示）+ 9×10 自适应棋盘（`Board`）+ 下方棋手席位条 + 棋盘操控底栏（`BoardNav`）。
   - **右侧工作台（`410px ~ 450px`，支持折叠/展开）**：根据当前工作空间动态渲染对应模块。
3. **底部状态栏（StatusBar）**
   - 实时展示当前工作空间任务提示、子力净分差、当前行棋方、步数（`当前手/总手数`）及将军告警（`红帅受将 / 黑将受将`）。

## 二、 首次启动与持久化策略

1. **冷启动默认状态**
   - 首次进入默认打开 `复盘分析 (study)`，棋盘展示 **32 子标准开局**（红方先行，手数 `0`），不再自动灌入虚构演示残谱，避免误导用户。
   - **空谱快捷引导**：当 `mainMoves.length === 0` 时，右侧「回合棋谱」与「复盘报告」页签分别提供引导卡片，支持一键：
     - `载入示范名局`（加载预置 12 手经典名局供体验）；
     - `开局定式`（一键切换至右侧「开局库」页签研习常见定式）；
     - `导入 FEN / 识盘`（打开导入/图片识别弹窗）；
     - `打开棋谱库`（浏览历史、现代名局、古谱与自存对局）。
2. **本地持久化（`localStorage`）**
   - **复盘会话 (`xiangqix_study_session_v1`)**：仅当 `workspace === 'study'` 时自动保存，包含当前盘面 `pieces`、基准起点盘面 `basePieces`、基准先行方 `baseTurn`、主谱 `mainMoves`、支线 `variationMoves`、分叉点 `branchOriginPly`、当前手数 `currentPly`、当前行棋方 `turn`、对局元数据 `metadata`、棋盘翻转状态 `flipped`。为避免快速步进或自动回放期间频繁同步序列化阻塞主线程，写入采用 **`350ms` 防抖调度**，并在切换离开 `study` 工作台、触发 `pagehide` / `beforeunload` 或组件卸载时立即同步落盘。
   - **本地棋谱库 (`xiangqix_library_v1`)**：保存预置名局、古谱及用户通过「存局」写入的 `LibraryGameItem[]`（含 `baseFen` 与紧凑着法数组 `movesData`，支持完整步进回放），采用 `300ms` 防抖落盘。
   - **残局破关进度 (`xiangqix_challenges_solved_v1`)**：持久化用户已破关的 `challengeId[]`，支撑顶栏总进度与「仅看未破」筛选。
   - **全局偏好 (`xiangqix_prefs_v1`)**：保存主题、字号、音效、棋盘/棋子工艺、简繁字形、主/副引擎 ID、双擎对比开关、MultiPV 条数、深度、线程数、Hash 内存等配置。
   - **按需延迟初始化**：示范名局棋谱、开局库盘面指纹索引图与当前盘面 FEN/PGN 导出字符串均采用惰性按需生成，不在冷启动或无弹窗常规走子渲染期间预先计算。

## 三、 四大工作空间详细交互逻辑

### 1. 复盘分析 (`study`) — 引擎研习主枢纽
- **引擎分析舱（`EnginePanel`）**：
  - **单按钮主控**：顶栏左上角仅保留唯一切换开关——未运行时为 **「开始分析」**，运行中为 **「暂停分析」**；待机区仅展示就绪提示文本，无重复按钮。
  - **引擎切换与安装引导**：支持切换预置引擎（`皮卡鱼 UCI`、`旋风 UCI`、`天机 UCCI`）或自定义导入引擎；若引擎状态为 `missing`，主体区替换为组件缺失提醒 + NNUE 权重说明 +「一键下载安装」与「引擎库管理」入口；安装中展示三阶段进度条并在完成后自动进入分析。
  - **双擎对比模式（`compareMode` / 快捷键 `C`）**：
    - 开启后在顶栏下方常驻 **对称配对条**：`主 [引擎A ▾] ⇄ 副 [引擎B ▾]`。
    - 选择冲突自动处理：若主副选到同一引擎，自动将另一槽位对调互换；点击中间 `⇄` 按钮可一键互换主副引擎。
    - 主副对比结果：顶栏输出「**双擎共识**（绿色，一致首推某着 + 分差 Δ）」或「**双擎分歧**（琥珀金，分别标出主/副主推着法 + 分差 Δ）」；棋盘上以翠绿（`#10B981`）与天青蓝（`#3B82F6`）区分主副箭头，共识时合并为 `[双擎共识]` 箭头。
  - **多主变（MultiPV）与威胁雷达**：
    - 悬停候选着法行，棋盘渲染金色半透明幽灵预览箭头；点击候选着法直接在棋盘上试走并进入分支。
    - 开启「威胁」按钮后，棋盘以红色虚线箭头标出对方下一步最具威胁的攻着。
- **连续双栏棋谱（`MoveList`）与存局入库**：
  - 按回合（红方 + 黑方）双栏展示着法、质量角标（`妙/优/良/缓/败`）与红方视角分值（`+0.45` / `-1.20`）。
  - 对局信息头提供 **「存局」** 与 **「收藏」** 快捷操作：点击「存局」可将当前起始盘面 `baseFen` 与全部实走着法压缩序列 `movesData` 一键存入棋谱库「自存对局」分类，并实时更新顶栏及弹窗分类统计数量。
  - 在任意历史手（`currentPly < mainMoves.length`）直接走棋或点击引擎候选着，若与主谱下一步不同，立即从该手分叉生成 **内联推演支线**（棋盘框呈现金边高亮并标出「推演分支中」）。
  - 支线顶部内嵌操作条支持：**「升为主线」**（替换主谱后续着法）或 **「返回主谱」**（丢弃支线回到分叉手）。
- **整局复盘报告（`GameReviewPanel`）**：
  - 红黑双方精准度百分比基于当前主谱各手 `quality` 标签实时加权计算（`妙=99, 优=95, 良=88, 缓=74, 败=48`），不再写死固定数值。
  - 内嵌局势演化曲线（`EvalGraph`），支持点击任意手跳步。
  - 自动筛选 `缓 / 败` 着生成 **关键失误诊断卡片**，点击 **「在此手重练」** 自动跳回失误前一手并要求用户在棋盘走出正确着法，系统实时判对错。
- **开局库（`OpeningBookPanel` — 右侧第三页签）**：
  - 与 `回合棋谱`、`复盘报告` 并列于 `study` 右侧栏，随当前棋盘局面实时计算 **盘面指纹（`piecesPlacement + turn`，天然兼容同形换手/变序还原）** 进行 O(1) 定式匹配。
  - **已命中定式节点**：顶栏展示当前定式名称（如「中炮对屏风马 · 进七兵」）、所属体系分类、样本对局量、行棋方及棋理短评；下方列表按出现频率降序展示流行后续着法，标注红胜/和棋/黑胜三段式比例条与明文百分比。悬停着法行在棋盘渲染金色幽灵预览箭头，点击直接走入该变例（若处于历史手则自动触发无感内联分支）。
  - **脱离标准定式或末端节点**：保留显示本谱最后一次命中的定式节点并提供一键 **「退回至最近定式节点」**；底部常驻 **五大经典开局体系骨架**（中炮过河车对屏风马、顺炮直车对横车、仙人指路转中炮、飞相局对左中炮、中炮对反宫马），支持一键载入演练。

### 2. 残局题库 (`challenge`) — 规模化题库检索与破局闯关
- **纯净防剧透布局**：隐藏引擎分析舱与左侧评估柱；棋盘上下席位条展示「挑战者（红方）」vs「古谱出处（如《百局象棋谱》《适情雅趣》）」。
- **右侧可规模化题库工作台（`ChallengeWorkbench`）**：
  - **破关总进度**：顶栏固定展示 `已破关 X / Y 关 · Z%` 及完成度进度条（持久化至 `xiangqix_challenges_solved_v1`）。
  - **多维检索筛选**：支持关键字搜索（残局名称/典籍/杀法说明）、古谱典籍下拉筛选（`百局象棋谱`、`心武残编`、`橘中秘`、`适情雅趣`、`竹香斋`、`梦入神机`）、难度分段筛选（`全部 / 进阶 / 高难 / 绝杀`）及 **「仅看未破」** 开关，当前内置 **12 道坐标核验经典残局** 并面向百关级扩展设计。
  - **精简卡片与手动核销**：每关卡片以 `典籍 · 难度 · 约 N 手杀` 纯文本无胶囊排版呈现，支持点击「待破 / 已破关」状态核销；重摆与支招仍统一收敛至棋盘底栏不重复。
- **自动应手、破关判定与支招**：
  - 玩家执红走子后，系统评估第 1 手是否命中预置正着（或后续走至大优胜势 `eval >= +5.0`）并自动标记该关为 **「已破关」**，随后延迟约 `620ms` 模拟黑方自动应手。
  - 点击底栏 `支招`：若在残局第 0 手，优先亮出古谱预置正着箭头与文字解析；若已走入变例，则调用引擎计算当前最佳应对。
- **底部主按钮**：固定展示 **「转入复盘分析」**（若已试走着法，文案自动显示为 `携带 N 手试走转入复盘分析`）。

### 3. 人机对弈 (`play`) — 沉浸实战对抗
- **纯净实战布局**：隐藏引擎分析舱与左侧评估柱；席位条展示「玩家（红方）」vs「电脑引擎（含让子标签）」。
- **右侧对弈面板**：
  - **开局让子**：`分先`（双方满子红先）、`让先`（双方满子黑先）、`让左马`（撤去黑方左马，红先）、`让双马`（撤去黑方双马，红先）。切换让子立即重开对局。
  - **电脑棋力档位**：`初级`、`中级`、`高级`、`大师` 四档。
  - **实战着法记录**：实时流式展示已走手数与每手中文纵线记谱，电脑思考时显示「电脑思考中…」。
  - **底部主按钮**：固定展示 **「转入复盘分析」**（有对局着法时显示为 `携带 N 手实战转入复盘分析`）。

### 4. 摆子编辑 (`setup`) — 专属摆局工坊
- **居中盘面 + 右侧专属工坊**：隐藏引擎舱、评估柱、席位条与复盘双页签，右侧整栏渲染 **「摆子编辑工坊（`SetupWorkbench`）」**。
- **布子与移除规则**：
  - 右侧红/黑双列子力库按传统象棋上限（车马炮士象各2、兵卒5、帅将1）显示剩余可用枚数，已满子力自动置灰禁用。
  - 选中右侧子力后点击棋盘空交点即可落子；点击棋盘已有非将帅棋子直接移除。
  - 红帅与黑将受保护不可直接移除，底部合法性状态条实时校验红帅/黑将是否均在位（缺一则禁用提交按钮）。
- **辅助控制**：支持设定先行方（`红方先行 / 黑方先行`）、`仅留将帅`、`恢复初始棋盘`、实时 FEN 预览与一键复制；棋盘底栏保留 `翻转` 可用，其余步进/悔棋/支招禁用。
- **底部主按钮**：点击 **「完成摆子 · 转入复盘分析」**，提交摆出局面并自动切入复盘分析。

## 四、 跨工作空间流转与状态交接机制

系统严格区分「导航切换」与「携带局面转入复盘」两种行为，防止用户误覆盖既有复盘进度：

```text
  [残局题库] ── 点击「转入复盘分析」 ──┐
  [人机对弈] ── 点击「转入复盘分析」 ──┼──▶ transferPositionToStudy(payload)
  [摆子编辑] ── 点击「完成摆子」     ──┤       1. workspace = 'study'
  [导入/棋谱库] ── 载入 FEN / 对局   ──┘       2. 写入 basePieces / baseTurn / moves / ply / metadata
                                              3. 清空旧支线与重练状态，rightTab = 'moves'
                                              4. 设置 isAnalyzing = true，自动持久化至 localStorage

  [任意模式] ── 点击顶栏「复盘分析」 ────▶ handleSwitchWorkspace('study')
                                              从 localStorage 恢复上一次复盘会话（不覆盖原研习进度）
```

> **设计重点**：当用户点击 `BoardNav` 的「回到开局 (`Home`)」或 `currentPly === 0` 时，棋盘恢复的是 `studyBasePieces` 与 `studyBaseTurn`（而非硬编码的 32 子标准开局），因此由摆子、残局、让子实战或 FEN 导入转入复盘后，前后步进跳转始终保持起点一致。

## 五、 棋盘坐标与数据协议约定（后端对接核心）

### 1. 棋盘坐标系 (`Position`)
- **行 (`row`)**：`0 ~ 9`，从上到下递增（标准未翻转视角下：`0~4` 为黑方半场，`5~9` 为红方半场；黑将九宫 `row: 0..2, col: 3..5`，红帅九宫 `row: 7..9, col: 3..5`）。
- **列 (`col`)**：`0 ~ 8`，从左到右递增（对应黑方 `1~9` 路、红方 `九~一` 路）。
- **ICCS 坐标映射（与 UCI/UCCI 引擎对接）**：
  - 列映射：`col 0..8` ↔ `'a'..'i'`
  - 行映射：`row 0..9` ↔ `'9'..'0'`（即 `iccsRank = 9 - row`，例如红方炮二平五 `(7,7)->(7,4)` 对应 `h2e2`）。

### 2. 核心类型契约（见 `src/types/xiangqi.ts`）
- **`Piece`**：`{ id, type: 'general'|'advisor'|'elephant'|'horse'|'chariot'|'cannon'|'soldier', camp: 'red'|'black', row, col }`
- **`MoveRecord`**：记录每半步（ply）的 `from`、`to`、`captured`、中文记谱 `notation`、红方视角分值 `evalScore`（单位：**兵/子力值**，如 `+1.25`；杀棋用 `mateIn`）、着法评级 `quality ('妙'|'优'|'良'|'缓'|'败')`、失误正着建议 `bestAlternative / bestFrom / bestTo`，以及落子后的 `piecesSnapshot`（用于前端 O(1) 跳手回放）。
- **`MultiPVLine`**：单条引擎候选主变，含 `multipv`、`depth`、`scoreCp`（**当前前端约定为红方视角分值，单位为分/百分兵折算后的浮点值，如 `+0.45`；若后端引擎返回红黑当前行棋方视角的 centipawn，需统一转换为红方视角并除以 `100` 传入**）、`mate`、`nps (kN/s)`、`hashfull (‰)`、`pvMoves`（中文着法数组）、`firstMove`、`summaryText`。
- **`EngineProfile`**：引擎档案，含 `id`、`name`、`shortName`、`protocol ('UCI'|'UCCI')`、`styleLabel`、`nnueFile`、`sizeMb`、`status ('missing'|'installing'|'ready')`、`installProgress (0..100)`。

- **`LibraryGameItem` 与 `CompactLibraryMove`**：棋谱库记录除基本元数据外，新增 `category ('master' | 'ancient' | 'user' | 'recent')`、`baseFen` 与压缩步法数组 `movesData: { from, to, evalScore?, quality? }[]`，加载时通过 `replayCompactMoves` 全量还原每手历史快照；棋谱库弹窗按分类实时统计数量，支持关键词搜索、胜负筛选（`全部 / 红胜 / 黑胜 / 和棋`）、多维排序（`默认 / 最新日期 / 手数最多 / 精准度最高`）、命中局数与胜和分布摘要及「保存当前对局入库」。
- **`OpeningBookNode` 与 `OpeningMoveStat`**：开局库节点以标准 FEN 盘面+行棋方核心串（`getPositionKeyFromPieces`）作为键名，包含 `openingName`、`category`、`plyDepth`、`totalGames`、`comment` 及流行后续列表 `nextMoves[]`（`notation`、`from`、`to`、`frequencyPct`、`redWinPct`、`drawPct`、`blackWinPct`、`targetOpeningName`）。

| :--- | :--- | :--- | :--- | :--- |
| **1. 引擎库管理与安装** | `engines` 初始态 + `handleInstallEngine` + `handleAddCustomEngine` | 扫描本地引擎目录、下载引擎与 NNUE 权重、校验自定义可执行文件 | `{ engineId }` 或 `{ filePath, protocol }` | 初始列表 `EngineProfile[]`；安装进度事件 `{ engineId, progress: 0..100, stage, status }` |

| **3. 威胁雷达分析** | `threatArrow` (`generateOpponentThreatArrow`) | 对当前局面交换行棋方执行 `null-move` 浅层搜索（如 depth 12~14）获取对方最大威胁着 | `{ engineId, fenFlippedTurn }` | `{ from: Position, to: Position, notation: string, scoreCp: number } \| null` |

> **规则与合法性备注**：前端 `src/utils/xiangqiRules.ts` 已实现完整的中国象棋走子合法性（含蹩马腿、塞象眼、炮隔子、将帅不对脸、应将与自杀保护）及 FEN/PGN 互转；内部采用 90 格扁平数组 `buildBoardGrid` 实现 O(1) 棋盘格查询，并通过“将/帅为中心向外射线/日字反探”完成 O(1) 将军校验；新增 `getPositionKeyFromPieces` 与 `replayCompactMoves` 用于开局库 O(1) 同形识别及存局完整重演。若后端同时保存 PGN/ICCS 走法，建议统一以 **标准象棋 FEN + ICCS 坐标串（如 `h2e2`）** 作为前后端传输基准格式。

### 引擎分析调度与前端渲染防阻塞契约（对接真实引擎时保持一致）
- **快速步进防抖与过渡调度**：在连续键盘翻步（`← / →`）或 `850ms` 自动回放期间，引擎分析任务（MultiPV 与威胁雷达）经过 **`120ms` 防抖** + React `useDeferredValue` 低优先级队列调度；当分析目标尚未追平当前最新盘面时，棋盘隐藏旧手推荐箭头以免误导，`EvalBar` 立即回退展示当前着法记录分值（或即时静态分值），保证 60fps 交互响应；真实后端/原生进程对接时同样建议在连续跳步窗口内取消或去抖 `stop` / `go` 指令。
- **三层隔离与精细化 Memo**：棋盘划分为「静态纹理与网格层（含 SVG `feTurbulence` 宣纸肌理与 `contain: layout paint style` 合成隔离）」、「动态箭矢层」、「交互落子与 90 格热区层」，配合全工作台组件 `React.memo` 与稳定回调引用，避免单步落子或悬停预览触发整盘与底纹重绘。
